# Decisions

Every choice made on top of `SPEC.md`, and every place the repository deliberately departs from it —
one line each, oldest first. **Read this index before any non-trivial change**, then open the few
entries it points you to; the full reasoning, measurements and rejected alternatives are in
[`decisions/`](decisions/), one file per decision.

**This file is an index, and it stays one.** It was a single 7,400-line log until 28 September 2026,
which had become too long to read, so it was written to and not consulted. Keep it short enough to
read whole:

- **A new decision is a new file**, `decisions/NNNN-slug.md` with the next number, headed by its
  title, plus **one line here**: the decision itself, as a rule a later change must respect, in at
  most about thirty words. Never append reasoning to this file.
- **A decision that reverses or narrows an earlier one** says so in its own file, and the earlier
  line here gains *Superseded — by NNNN* (or the part that changed). Do not rewrite the earlier
  file's reasoning; history is the point of keeping it.
- An entry's line is the rule as it stands. When a later entry changed only part of an earlier one,
  the earlier line states what still holds and the later entry holds the rest.

- [0001](decisions/0001-swift-native-on-both-ends-ios-26-macos-26-minimum.md) Both ends are native Swift: a universal SwiftUI client with a real iPad split view and a Swift server, minimum iOS 26 and macOS 26, no back-deployment shims.
- [0002](decisions/0002-uncommitted-working-state-only-no-committed-history.md) Granita shows only uncommitted state from HEAD to the working tree: staged, unstaged, untracked as added, ignored never; browsing committed history is v2.
- [0003](decisions/0003-public-repository.md) The repository is public, because on GitHub Free a `protect-main` ruleset only enforces on public repositories.
- [0004](decisions/0004-xcode-cloud-for-delivery-over-github-actions-plus-a-release.md) Delivery is Xcode Cloud, not a release script; its workflow is server-side state outside git. The phone ships to TestFlight; the unsandboxed Mac app ships Developer ID, notarised.
- [0005](decisions/0005-the-generated-xcode-project-is-committed-not-gitignored.md) `Granita.xcodeproj` is committed because Xcode Cloud needs shared schemes present; `project.yml` stays the only source, `make project` the only generator, and CI fails on drift.
- [0006](decisions/0006-corebrandingdomain-a-module-the-spec-s-tree-does-not-list.md) Branding constants (product name, bundle prefix, Bonjour type, URL scheme, Application Support directory) live in `CoreBrandingDomain`, the single home both units import.
- [0007](decisions/0007-the-agent-harness-lives-under-one-claude-root.md) *Superseded — the `.ai/` harness tree later entries cite (move itself unrecorded).* The agent harness lives under a single `.claude/` root rather than an `.ai/docs` plus `.claude/` split.
- [0008](decisions/0008-golden-diff-fixtures-are-generated-and-committed-before-the.md) Golden diff fixtures are generated by `Scripts/make-fixture-repo.sh` against real git, which asserts the traps the parser relies on, and the .diff outputs are committed so tests need no git.
- [0009](decisions/0009-fixtures-must-be-independent-of-where-they-are-built-and.md) Committed fixtures must not depend on build location; `make verify-generated` regenerates from a differently named directory and diffs, and only the worktree listing's root is rewritten to a token.
- [0010](decisions/0010-presentation-depends-on-ui-not-the-other-way-round.md) `Presentation` depends on `Ui`, never the reverse: `Ui` holds stateless views taking values and closures, with no test target; `Presentation` owns the `@Observable` view models and composes screens.
- [0011](decisions/0011-the-app-icon-is-three-drawings-and-the-two-sets-need.md) iOS icons are full squares without alpha or a baked mask; macOS icons are shaped with alpha at every slot; rasterise through CoreGraphics, and `make icons` stays manual, outside verify-generated.
- [0012](decisions/0012-no-snapshot-test-ci-job-until-there-is-ui-to-render.md) A required CI job lands only when it asserts something, and its name joins `protect-main.json` in the same pull request; the snapshot job waited for the first `Ui` slice.
- [0013](decisions/0013-merging-to-main-publishes-and-the-build-number-is-not-ours.md) Every squash merge to `main` publishes a build, so version and changelog must be right before merge; `ci_pre_xcodebuild.sh` writes `CURRENT_PROJECT_VERSION` from Xcode Cloud's run number, never hand-bumped.
- [0014](decisions/0014-the-xcode-cloud-build-number-is-a-team-wide-counter-and.md) Xcode Cloud's build number is an account-wide counter with gaps; App Store Connect accepts that, so Granita keeps Apple's counter rather than maintaining its own.
- [0015](decisions/0015-the-ci-skip-token-silences-github-actions-too-so-it-goes-in.md) The CI-skip token never goes in a branch commit, where it silences required checks; set it only on the squash subject via `gh pr merge --subject`, not the PR title.
- [0016](decisions/0016-the-committed-package-resolved-is-the-xcode-union-not.md) The committed Package.resolved is Xcode's union graph, not SwiftPM's; regenerate it with `make resolve` after `swift test` rewrites it, and CI asserts it covers the Xcode graph.
- [0017](decisions/0017-three-settled-gaps-in-the-diff-model-and-one-spec-error.md) A `--numstat -z` rename is marked by a trailing TAB, not an empty field; `DiffLine` always encodes `needsMeasurement`; control characters are 0 columns and East Asian Ambiguous 1.
- [0018](decisions/0018-the-display-columns-fixture-was-committed-empty.md) A fixture generator must assert its outputs are non-empty, not merely that it ran; the display-columns case stages its file so `git diff HEAD` shows it.
- [0019](decisions/0019-coverage-is-reported-per-kind-of-test-and-the-second-column.md) Coverage is reported per kind of test (unit, ui, snapshot, all), each a bundle directory, in lines and regions; the all row is a merged-profile union, not a sum.
- [0020](decisions/0020-the-parser-reports-what-the-diff-text-says-and-nothing-the.md) The parser reports only what diff text states (path, old path, refused, gitlink, hunks), never status or line counts, which come solely from the change-set comparison.
- [0021](decisions/0021-the-parser-never-fails-because-a-truncated-hunk-is-an.md) The diff parser never throws: a hunk truncated by the size guard is normal input, so unrecognised content is skipped and everything before it kept.
- [0022](decisions/0022-splitting-diff-output-on-a-newline-character-silently.md) Split diff output on the newline byte, never the "\n" `Character`, because Swift treats CRLF as one grapheme; the trailing CR is preserved content counting zero columns.
- [0023](decisions/0023-a-conflict-marker-is-recognised-by-state-not-by-a-prefix.md) Conflict separators and terminators count only while an opener is open, tracked across the whole file; markers are exactly seven characters, and `|||||||` is recognised for diff3 and zdiff3.
- [0024](decisions/0024-the-word-diff-measures-similarity-over-non-whitespace.md) The word diff's 0.4 similarity floor is a token-bag overlap over non-whitespace tokens only; whitespace remains a token inside the comparison itself.
- [0025](decisions/0025-the-marker-for-a-missing-trailing-newline-does-not-break-a.md) A "No newline at end of file" marker does not break a deletion-then-addition run for word-diff pairing; markers are never paired and number neither side.
- [0026](decisions/0026-the-invocation-must-pin-the-diff-path-prefixes.md) Every diff-family invocation must pin the `a/` and `b/` path prefixes, because `diff.noprefix` in user config would silently strip two characters from every parsed path.
- [0027](decisions/0027-the-snapshot-coverage-row-is-measured-over-the-view-layers.md) The Snapshot coverage row is measured over the view layers only, not the whole package; changing how a row is measured leaves it unjudged for one run.
- [0028](decisions/0028-the-file-tree-carries-structure-and-identity-and-nothing.md) The file tree takes a two-field entry, identifier and repo-relative path, and status, stats and viewed state are joined by identifier one layer up through a boundary mapper.
- [0029](decisions/0029-the-flat-toggle-is-not-a-second-shape-the-domain-owes.md) The flat file list is the change set's input order unchanged (git path order, matching the scroll); the domain builds only the tree, never a flattened second shape.
- [0030](decisions/0030-directories-above-files-and-the-sort-is-over-what-the-row.md) The file tree sorts directories above files, each group alphabetically, case-insensitive with a raw-name tiebreak, locale-independent, comparing the compacted name the row displays.
- [0031](decisions/0031-compaction-folds-directories-never-a-file-and-the-row-is.md) Compaction folds only chains of single-child directories, never a file into its directory; a compacted row is identified by its deepest directory; directory aggregate stats are deferred.
- [0032](decisions/0032-a-dead-browser-is-replaced-and-only-a-refusal-that-repeats.md) A dead Bonjour browser is replaced after a second; `DefunctConnection` means refusal only after three consecutive deaths, `PolicyDenied` immediately, and replacements continue five seconds apart once refused.
- [0033](decisions/0033-the-git-client-asks-a-closed-set-of-questions-not-an.md) The git client exposes a closed enumeration of questions, each building its argument vector in one place and declaring which exit codes count as answered; errors carry git's stderr verbatim.
- [0034](decisions/0034-every-configurable-part-of-an-invocation-is-pinned.md) Pin every configurable invocation part: `--src-prefix=a/ --dst-prefix=b/` on diffs, status with `--untracked-files=all --renames --no-branch --no-show-stash`; diff flags go right after the subcommand.
- [0035](decisions/0035-a-fixture-repository-configured-to-defeat-the-product.md) The `.fixtures/hostile` repository carries config that defeats every unhardened invocation, and the generator asserts each trap with the others neutralised so a missing pinned flag turns tests red.
- [0036](decisions/0036-an-output-cap-truncates-and-truncating-means-killing-git.md) The git output cap truncates rather than fails: hitting it or the timeout kills git, never its process group, and a truncated run's exit status is not judged.
- [0037](decisions/0037-arguments-are-bytes-and-so-is-a-repo-relative-path.md) Git argument vectors are `[[UInt8]]` and repo-relative paths carry bytes, with text as the lossy projection for display and wire; only the checkout location stays a string.
- [0038](decisions/0038-an-opaque-identifier-is-a-bare-string-on-the-wire.md) Opaque identifiers encode as bare JSON strings, not `{"rawValue": …}`, via `RawRepresentable` and `CodingKeyRepresentable`, so they serve as URL path components and dictionary keys.
- [0039](decisions/0039-what-the-first-git-slice-deliberately-leaves-out.md) *Superseded — batched `hash-object --stdin-paths` landed in M2 (0040); binary locator never recorded.* The first git slice omits git-binary resolution (the executable is a constructor parameter) and `hash-object --stdin-paths`, deferring both to the layers that need them.
- [0040](decisions/0040-the-rest-of-m2-and-the-three-things-real-repositories-said.md) Session labels come from `custom-title`, never `last-prompt`; each session maps to its closest containing worktree; nested-worktree directories are excluded from hash batches; an unborn HEAD reads as forty zeroes.
- [0041](decisions/0041-claude-design-is-asked-with-baselines-and-prose-and-nothing.md) Design prompts are pasted in chat, never committed; Claude Design receives committed snapshot baselines in all four layouts plus prose naming the stock idiom, never uploaded tokens or mocks.

- [0048](decisions/0048-macos-refuses-a-ten-year-tls-certificate-which-is-why.md) The ten-year certificate fails Apple's 398-day cap under SSL policy, so clients replace default trust evaluation with fingerprint pinning; a test asserts that exact refusal.

- [0051](decisions/0051-the-six-words-are-a-second-credential-not-a-rendering-of.md) The six spoken words are an independent random credential from a 128-word list (42 bits) redeeming the same pairing; spending either spends both; typed input is normalised first.
