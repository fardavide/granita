Granita 0.19.0  ·  one Mac app  ·  the window a reader reads in

The window reads the disk. The menu bar keeps answering for the phone.

Merged, Granita is one bundle with two surfaces that never report on each other. The status item goes on answering the question it answers today — can the phone reach this Mac — and the new window reads worktrees through GranitaRepository bound to the server's own registry: no socket, so no interest in whether anything is serving.

Almost every call below follows from keeping those two apart. The window never mentions the server, the menu never mentions reading, and the one place they touch is a single new row in the menu that opens the window.

Drawn against
macOS 26 at 1:1, light and dark, against main today. The images attached to the message were the side-by-side round's, so the baselines shown here were pulled from the repository instead.

Read this first  ·  four things at main that change the drawing
This Mac will discover itself.
The merged process browses _granita._tcp while advertising it, under MachineName.computer. Unfiltered, the discovered list gains a row for this Mac under its Bonjour name — a second way to the same worktrees, through TLS, a pin and a pairing with itself. The browse has to drop the instance the server registered. Every §4.4 frame is drawn with it dropped.
One bundle is one Local Network grant.
Today the server's .failed and the Client's permission-refused are two decisions in two bundles. Merged they are one privacy entry, so the reader cannot find other Macs exactly when the phone cannot find this one. That is what makes §4.4's strange state ordinary: it is the menu's Not serving seen from the window, and it gets the menu's button. This Mac is not affected by it at all.
The seam is built on one side only.
GranitaRepository is the boundary on the Client side. On the server side WorktreeRegistry and WorktreeService are made inside MacComposition.init and handed only to ApiDependencies; nothing keeps them. The local repository needs the composition to hold them, to map ApiError onto ApiFailure, and to report a read route of its own: the protocol's default reports .reading(.unknown), which the loading block spells “Waiting for your Mac's response.” There is no response to wait for.
One server state does stop This Mac.
StoreLockingServerHost takes the store's lock for the whole launch. When another process holds it, a reader writing viewed marks, names and reviews into that document is the two-writers case design-mac's answer (b) already refused. So blocked by another process is the single exception to “the local source works when the server does not”, and §4.7 draws it as its own state. Failed and stopped are not exceptions.
Sentences the merge makes false
General › Startup: “Granita has no window and no Dock icon. If it is not running, your phone finds nothing.” The sidebar's no-projects text, which sends a Mac reader to “Granita's menu bar item on your Mac”. The connecting failure's “Check that Granita is running on your Mac”, which cannot happen on This Mac. The gone worktree's fallback title This worktree, which now sits beside This Mac.
Settings is not quite as briefed
SettingsTab and the window ship General, Projects, Devices, Review, Connections, Advanced — Review before Connections, not after. GranitaSettingsScreen's doc comment still says five tabs. Nothing here depends on the order; it is recorded so §4.3 is reviewed against what is built.
The list has no refresh on a Mac
The sidebar's only refresh is .refreshable, and on macOS that modifier draws no gesture. Without a Refresh command the list is read once per window and never again. The drawing adds one: a toolbar button at the head of the sidebar and ⌘R in the View menu, both calling the onRefresh the view already takes.
§8's last question  ·  what it is, as one thing

A server with a reading room, and a door between them

The window should feel like Preview open on a long document: a list of what there is to read, the document, and its contents beside it. Nothing in it is about serving, pairing phones or ports. A reader who never owns a phone should be able to use it for a year without learning that Granita serves anything.

The Dock icon makes the whole thing behave like Mail with no window open: running is normal, closing a window means closing a window, and clicking the icon brings the window back where it was. That is the ordinary Mac contract, and it is what keeps close from ever reading as quit.

The status item's “open me twice a year” character survives, and it survives because of the local seam. If the window depended on the server, every reading problem would send the reader to the menu bar to find out why, and the status item would become a place visited daily. It does not, so the menu bar stays the phone's business. The one new habit is Show Worktrees, which is a door rather than a panel.

The three surfaces, each in one line
Status item — the Time Machine menu, unchanged: whether the phone can reach this Mac.
Settings — Terminal's Settings, unchanged: six plain panes, one of them a door target for the window.
The window — Preview on a long document: sources, worktrees, the diff and its contents. Sat in for an hour, closed without consequence.
The calls  ·  recommendation first, then what it beat

Twelve calls

1 · 6(c)
Choosing a source is a pop-up menu at the head of the sidebar.
Recommended
One stock pop-up button, labelled with the source it is showing, above the worktree list it chooses for. This Mac is first and ticked by default; discovered Macs follow under a heading; a Mac this device has not paired with ends in an ellipsis because choosing it asks for more. The phone's whole screen becomes six rows, which is the right size for a choice made a few times a year. §4.4 draws all six states.
Rejected: sources as sections of the same sidebar, which puts two Macs' 122-second reads on screen at once and gives the sidebar two meanings; a toolbar control over the diff, which is the far side of the window from the list it changes; a chooser window that opens first, which asks a question whose answer is This Mac nearly every time; and the phone's pushed screen, which is where the back-chevron came from.
2 · 6(a)
The file selector is a trailing inspector, open by default, 240pt.
Recommended
SwiftUI's .inspector, toggled by sidebar.trailing at the end of the toolbar and ⌥⌘0. The decisive reason is that DiffPaneLayout already has a fold — showsSelectorColumnToggle — and an inspector is the only Mac container that can fold on its own. The list keeps both of its jobs: it jumps, and it stays on screen to show how much of the change set has been read.
Rejected: a third split-view column. NavigationSplitViewVisibility has .all, .doubleColumn and .detailOnly and no case that hides the middle column alone, so the existing fold would have nothing to bind to — and with nothing chosen the window would show two empty columns. A popover, which gives up the second job the moment it closes. A sheet at a detent, which is the thumb idiom the brief rules out.
3 · 6(b)
The review takes the same inspector, in the files' place, while it is open.
Recommended
This is the iPad's rule moved unchanged: showsReviewColumn wins the slot, showsSelectorColumnToggle goes while it has it, and the toolbar's bubble-and-count is the way back. Nothing new is decided; the Mac binds the same value to a different container.
Rejected: a sheet, which stops the reader scrolling the code the comments are about; a separate window, which outlives a change of worktree and would show one worktree's review beside another's diff; a fourth column, which at 260 + 760 + 240 + 280 is 1540pt and wider than a 13-inch MacBook Air's 1470pt screen.
4 · 6(d)
One window. The Dock icon reopens it on the last source and worktree.
Recommended
A single Window scene with .defaultLaunchBehavior(.suppressed) and restoration off, which is 5(d) in two modifiers. Clicking the Dock icon with no window open opens it; with one minimised, restores it. What it reopens on is remembered in defaults rather than by window restoration, so a login launch still opens nothing. Reopen has to be handled explicitly: the first Window in the scene body is the invisible SettingsOpener, declared first on purpose.
Rejected, for now: a window per worktree. Two agents on one task is a real reason to want two diffs side by side, but the Client has one list model per screen and one review store per worktree, and two windows editing the same marks is a synchronisation problem nobody has designed. The cheap later form is Open in New Window on the row's context menu over a WindowGroup(for: WorktreeID).
5 · 6(e)
Keep pairing for a remote Mac. Drop the camera. Six words, typed or pasted.
Recommended — the call you left open
A two-Mac household is the realistic remote case — a laptop reading what an agent wrote on a Mac Studio — and the Client already pairs, so removing it saves nothing. The camera is the wrong half of it here. To scan, the reader would have to carry a laptop round to face another Mac's display; and com.apple.security.device.camera would move from GranitaMobileMac.entitlements onto the one process that listens on a socket and execs git. The six words are already a first-class credential, and this Mac has a keyboard. The field also accepts the words pasted as one line, which is what the Devices pane's Copy button already produces.
The cost, stated rather than hidden: the words path is trustingFirstAnswer — it pins whatever key answered — where the QR carries its pin in the link. On a home network that is a first-use trust decision rather than a verified one. Rejected: keeping the camera for parity with the phone; and dropping remote Macs, which deletes working code to save one sheet.
6 · 6(f)
Say it once, in the source menu. Never in the window's chrome.
Recommended — your 5(e) call
This Mac carries a menu-item subtitle — “Read on this Mac, without the network” — because the menu is the one place sources are compared, so it is the one place the difference is a choice. In the window the source appears only as the second half of the title's subtitle, granita · This Mac, which is also what tells two remote windows' worth of Macs apart. There is no banner, badge or line about the server, ever: the window holds only the reader (5(c)), and the status item already answers that question.
Rejected: a sidebar footer or badge saying local, which is chrome a reader sits in front of for an hour to learn something once; a Server not running — still reading notice, which makes the window report on the server and invites the question it is trying to answer; and saying nothing anywhere, which leaves the menu's two kinds of row looking the same when they cost differently.
7 · 5(g)
Default 1260 × 800pt. Minimum 640 × 480pt.
Recommended — derivation in §4.5
The width is three columns added up: a 260pt sidebar, a 760pt diff and a 240pt inspector. The height is what a 13-inch MacBook Air shows under its menu bar and above its Dock. The minimum is the diff's floor plus the inspector's, with the sidebar folded: 420 + 220. Unlike Settings, it resizes; unlike Settings, nothing in it is a fixed-size picture.
Rejected: the iPad's 320 / 320 / 554, which is iOS type sizes measured in iOS points; and a fixed size like Settings, which would forbid the one thing a Mac reader will do in the first minute — make the diff wider.
8 · 4.2
Show Worktrees, first in the menu's second group, in every state.
Recommended
Directly under the status line's divider and above Pair a device…. No ellipsis, because it asks nothing further. When the window is already open the same row activates the app and brings the window forward; the label does not change. It is enabled in all six server states, because the window always has something true to say — including when the store is held by another process. §4.2 redraws the menu.
Rejected: Open Granita, which names an app that is already running; above the status line, which takes the glance's first line away from the glance; a group of its own, which is a fourth group for one row; and a verb that flips to Hide Worktrees, which makes a reader read the row every time and duplicates ⌘W.
9 · 5(a)
Close closes. Quit quits, with no alert, from either menu.
Recommended
The red button and ⌘W close the window; the Dock icon stays lit and the status item stays put, which is how a Mac shows that an app is still running. ⌘Q from the app menu and Quit Granita from the status menu are the same act and behave the same. This wants a UI test in GranitaMacUiTests rather than trust: a SwiftUI app whose only window scene is closed can terminate, and here that would be a server that stopped for a reason its owner cannot see.
Rejected: a Quit Granita? alert, which a login item would show every time its owner quits it on purpose; and hiding the Dock icon when the window closes by switching activation policy, which breaks 5(a) and makes the Dock icon a window indicator that jumps in and out of ⌘-Tab.
10 · 4.5
The back-chevron goes because the detail stops being a stack.
Recommended
On the iPad the detail column is a NavigationStack and a chosen row is pushed onto it, which is where the chevron comes from and why the worktree list is replaced by Files in the iPad baseline. On the Mac the list binds a selection — List(selection:) — and the detail draws the chosen worktree directly. Nothing is pushed, so there is nothing to go back from, and the worktree list stays where it is. The iPad keeps its links, per 5(j).
Rejected: hiding the chevron with a toolbar modifier, which leaves a push the reader cannot see and a stack that still needs a way out.
11 · 5(i)
The row gets nothing new. The file count simply stops dropping.
Recommended
The Mac's text styles are smaller than iOS's — headline 13pt against 17, subheadline 11 against 15 — so the 260pt sidebar holds more than the iPad's 320. The second line has about 190pt, and the fixture's widest, granita · 34 files · +1,204 −318, needs about 186. What the width buys is that the first field in the drop order stays on realistic rows. Spending it on a new field would make the drop order live again on exactly the rows it just stopped touching.
Rejected: the branch under an alias, which is the rename sheet's business; and a single-line Mac row, which would respend the two name tiers.
12 · 5(c)
Nothing moves off the status item, and the phone's settings sheet does not come to the Mac.
Agreed, and drawn so
5(c) holds as written. What it leaves open is where the reader's own preferences go, since on the phone they live in the sheet behind the sidebar's Review settings…. On the Mac they become the View menu, which is where a Mac puts them: Side by Side, the code size as ⌘+ ⌘− ⌘0, and Code Colours. Appearance follows the system, as Settings does. For This Mac, Review settings… becomes a door to Settings › Review — the same door Pair a device… is to Devices. For a remote Mac it opens the existing review form as a window sheet, since those two values belong to that Mac. §4.3 draws the View menu.
Rejected: a seventh Settings pane for the reader, which breaks 5(c); and bringing the phone's sheet across whole, which puts a forced-appearance picker and Follow system code size on a platform with no Dynamic Type.

§4.1  ·  the status item

It keeps answering the same question, and it becomes a better answer

Recommendation: no change. It says whether the phone can reach this Mac, in three symbols, with no text. A Dock icon and a window do not give it a second job — they take one away. Under LSUIElement the symbol had to stand for “Granita is running” as well, because nothing else could; after the merge the Dock and ⌘-Tab say that, and the triangle means only what MenuBarLabel's doc comment already says it means.

It must not learn anything about the window. A symbol that changed while a worktree was open, or counted what was unread, would be the menu bar reporting on reading — and 5(f)'s arithmetic applies to anything it counts.

Rejected
A fourth symbol for “serving, and the reader is open”, which answers a question nobody asks the menu bar. Dropping the status item now that there is a Dock icon, which 5(c) rules out and which would hide the server's state whenever the window is shut — the normal case for a login item.

§4.2  ·  the menu, and the one row it gains

One row, under the glance, in every state

Show Worktrees goes first in the second group, between the status line's divider and Pair a device…. The first line stays the glance. The second group is where the menu's verbs live, and this is the one a reader will press most.

When the window is already open the row activates Granita and orders the window front — the same thing a Dock click does — so pressing it is never a no-op, which is the thing this project refuses to ship. The label does not change with the window's state.

It is enabled in all six server states. Serving or not, the window can read This Mac; blocked, the window opens and says in one sentence why This Mac cannot be read and that other Macs can. Pair a device… keeps its own rule, disabled under Not serving, because the QR encodes an address that does not exist.

Why the menu does not change otherwise
MenuBarContent's doc comment says each row earns its place because “this menu is the entire app when Settings is shut”. That reason expires, and the rows stay anyway, each for a reason of its own: the status line copies an address nobody can memorise, Pair a device… is the one gesture a new phone needs, and a login item needs a Quit that does not require opening a window first. The doc comment is what changes.

§4.3  ·  the Settings window, as context

A fixed panel beside a resizable document is the most ordinary thing a Mac does

It is not wrong to put a differently shaped window beside it. Mail, Safari, Xcode and Terminal itself pair a fixed Settings panel with a resizable main window, and they are different shapes because they are different kinds of window: one is opened, changed and shut; the other is sat in. Making the reader match Settings would forbid resizing it; making Settings match the reader would undo 5(g). The visual language they share is the one that matters — stock controls, semantic colours, SF Symbols, and the grouped form's section headers.

One sentence in it becomes false. General's Startup footnote reads “Granita has no window and no Dock icon. If it is not running, your phone finds nothing.” It is the only line in the six panes the merge contradicts. Suggested: “Closing Granita's window leaves it serving. If Granita is not running, your phone finds nothing.” — the first sentence is the thing 5(a) most needs a reader to know, and this footnote sits under the toggle that decides whether Granita runs at all.

Two doors into it from the window
The window opens Settings on a particular pane in three places, all through the requestSettings(showing:) the menu already uses: Open Projects Settings… when This Mac has nothing enabled, Open Local Network Settings… is the system's own pane rather than ours, and Review settings… for This Mac lands on Review. No pane is added and none is redrawn.

5(g)  ·  the default, 1260 × 800pt, and where each number comes from
7.2pt
One character of code: codePointSizeBesideTheSelector is 12pt, because the inspector is beside it, and SF Mono advances 0.6em.
60pt
The gutter at four figures, by DiffGutter's own rule at 12pt: 4 + 4 × 7.2 + 9, then the 12pt marker and 6pt gap.
760pt
The diff. It is the width the side-by-side round already drew the Mac at, and it holds (760 − 60 − 16) ÷ 7.2 = 95 characters unified and about 45 a side split — past the 554pt, 67-character width §6(a) calls pleasant, and close to the 100-column line length most of these repositories are formatted to.
260pt
The sidebar. The iPad's 320 at a 17pt headline is 320 × 13 ⁄ 17 = 245 at the Mac's 13pt; 260 is what lets the file count survive the fixture's widest row (call 11).
240pt
The inspector. The iPad's 320 at a 15pt subheadline is 320 × 11 ⁄ 15 = 235 at the Mac's 11pt.
800pt
A 13-inch MacBook Air is 1470 × 956pt; less a 37pt menu bar under the notch and a default Dock, about 850pt is visible. 800 fits with room for the shadow and shows (800 − 52) ÷ 19 = 39 rows of code under the toolbar.
The minimum, 640 × 480pt, and what folds on the way down
420pt
The diff's floor: the phone's 49 characters at 12pt, 49 × 7.2 + 60 + 8. It also keeps side by side above that round's 20-a-side floor, at 22 a side, so the toolbar item never has to disable itself inside the window's own range.
220pt
The inspector's minimum, where the file row has dropped its figures and still holds a name.
900pt
Below 260 + 420 + 220 the sidebar folds, which the split view does on its own. Folding it first is right: a reader switches worktree a few times an hour and reads the whole time.
640pt
420 + 220. Below this the only thing left to fold is the inspector, so this is the floor. It is 20pt from Settings' 620 by coincidence; neither number is derived from the other.
480pt
A 52pt toolbar, one 46pt file header and 20 rows of 19pt.
one constant
DiffPaneLayout.selectorColumnWidth is 320 and the Code size screen subtracts it. On the Mac it is 240, so it has to become a per-platform value — not a changed one, per 5(j).
§4.5, two more states  ·  nothing chosen, and a worktree that is no longer listed

Nothing chosen is NoWorktreeChosenView unchanged, in the detail, with the toolbar holding only the source's name. It is drawn only while the sidebar is listing: when the sidebar is itself an empty or failed state, the detail shows nothing, because “Pick one from the list” under a sidebar with no list is an instruction that cannot be followed. The iPad draws exactly that today; the Mac gates it.

No longer listed replaces the diff rather than titling it This worktree the way the iPad does. On a Mac the list and the detail are on screen together, so a diff under no highlighted row reads as the list being wrong — and its viewed marks and comments would be refused with worktreeGone. The name is the one captured when the row was chosen. There is no button: the next move is a row in the sidebar.

Drawn at 680 × 460pt
Above the minimum and below the 900pt at which the sidebar would fold with a worktree open. Neither state has a worktree open, so the inspector is not shown and the sidebar keeps its width.

§4.4  ·  choosing a source

The phone's whole screen, as the menu behind one pop-up button

This Mac is always the first row and never depends on the rest of the menu. Everything ServerDiscoveryView can say lives below its divider, in an Other Macs group, and each of the phone's six states becomes one or two rows there: a disabled line that says what is happening, and the one control that acts on it where one exists. The phone's Copy Logs survives only in the failure, where it is the one thing to do.

§4.7  ·  the states only a Mac reader can land in

The server's state is not an input to This Mac — except through the lock

Not serving is drawn as the reading state, unchanged. The only difference on screen is the symbol in the menu bar and what its menu says. The way to make that impossible to get wrong is structural: the local repository is built in MacComposition from the registry, the service and the store, and never from ServerMacModel.serverState. Then a baseline of this window with the host held in .failed asserts it.

No projects yet gets a real button on the Mac, because here the fix is one window away: Open Projects Settings…, through the same requestSettings(showing:) the menu's Pair a device… uses. For a remote Mac the phone's sentence stays, naming that Mac, because nothing on this one can fix it.

Blocked by another process is the exception from the findings, and it says so in one sentence with the holder's name, as the menu does. It has no button: the fix is quitting a process this app did not start, and Quit Granita would be the wrong process. Other Macs remain one click away in the pop-up.

A long read is 5(f) on screen. Only the reading stage exists for This Mac — there is nothing to find or verify — so the block starts at Reading worktrees, and after ten seconds it grows the clock and the sentence the phone already carries about enabled projects. Its second line is the new route: Running git on this Mac, in place of Waiting for your Mac's response.

Flagged  ·  for the pull request rather than the drawing

Nine things to decide or check while building it

Keep the server's bundle identifier.
Its Keychain TLS identity is what every paired phone pins, and its login item and Local Network grant are registered to it. What the merge loses is the Mac Client's own Keychain of remembered Macs — a store with almost no one in it, since that build was never shipped.
This Mac's review is one copy, not two.
MacReviewCommentStore wraps a UserDefaults copy around the repository so a closed laptop costs a phone nothing. On This Mac the two are the same disk; bind the local source to the repository alone, or the review settings pane's counts and the window can disagree.
The registry swallows git failures.
(try? await service.worktrees(in:)) ?? [] in projects(), worktrees(inProject:) and resolve(_:). A Mac with broken git lists nothing, which on This Mac is a state with a known cause and a pane that shows it.
The camera leaves with the Client's Mac entitlements.
Per call 5: GranitaMobileMac.entitlements is not merged into the server's, and NSCameraUsageDescription stays in the phone's Info.plist only. The six-word path's first-answer trust is the stated cost.
SettingsOpener may be removable — check before deleting.
It exists because an LSUIElement app cannot open Settings without a window of its own. A regular app can. Until it goes, Dock reopen and the Window menu must be pointed at the reader explicitly, since the opener is the first Window declared.
Doc comments that describe the old app.
MenuBarLabel (“the whole of Granita's presence on the Mac”), MenuBarContent (“the entire app when Settings is shut”), GranitaMacScene (“no Dock icon and no main window”), WorktreeSplitScreen (“no macOS surface presents this screen”). Each carries an argument that the merge ends.
The first Client views ever rendered on a Mac.
The Mac snapshot kind exists for the server; the reader's views have only iOS destinations. Every frame in §4.4–4.7 is a candidate baseline — fourteen states, light and dark, no device axis — and the window's 640 × 480 minimum has to be asserted from inside the app, as design-mac said of Settings.
One layout constant becomes per-platform.
DiffPaneLayout.selectorColumnWidth is 320 and the Code size readout subtracts it. The Mac's is 240. Branch the value; do not change the phone's.
A test that closing is not quitting.
Open the reader, close it, assert the status item is present and the host is still serving. It is the one behaviour in 5(a) a snapshot cannot photograph, and the failure it prevents is silent.
