Five of the specification's premises do not survive the code that is already written, and those are first, because four of them change what gets drawn.

The problem, in Davide's words — not sent yet
One sentence, and the date, in your words. I have deliberately not written it for you, and I have not paraphrased the brief into it either: everything below argues from the code and from the specification, and the one thing that can only come from you is what you are actually trying to fix.

The rest of the brief needed nothing. What follows treats every surface as a first drawing, and the connection log — the one thing that exists — as a review.

Read in this order: the five premises, then the two decisions that constrain every tab (what the status item says, and what the window is), then the tabs.

Five premises, measured against the code before anything was drawn
DOES NOT APPLY
Port 8737, fallback, persisted
The advertised path has no port to choose. Four recorded runs bound 59144, 59145, 53613, 53611. defaultPort is read only by the CLI's --port.
CANNOT OCCUR
The escape hatch is on, so warn
MacComposition hard-codes requiresAuthentication: true and never offers the hatch. Two specified states are unreachable, and the honest warning is a different one.
WRONG VALUE, SHIPPING
A log row names the source
It names this Mac. request.head.authority is the address the phone dialled, identical for every device — and the rate limiter is keyed on it.
NOT REDEEMABLE
Six words instead of the camera
spoken(for:) maps the first 6 of 32 hex characters. redeem matches the whole code, so the words open nothing today.
NOT IN THE STORE
Devices with last-seen times
StoredDevice holds pairedAt and nothing later. Last-seen exists only for this run of the server, which changes what the row can honestly say.

The third one is the only one I would call a bug, and it is in the tab that ships. It is worth reading before the drawings, because it is also the answer to open call (e): a log whose rows cannot tell two phones apart cannot differ in kind or in reason, and the fix is one value, not a layout.

Open call c  ·  WHAT THE ICON SAYS

Three symbols, and the count only when there is one

Recommendation. Serving is arrow.trianglehead.branch, as built. Starting is hourglass, as built. Not serving is one symbol for both failure and stop — exclamationmark.triangle, unfilled. The menu bar answers one question, which is whether the phone can read this Mac; the reason is one click below.

The count is a Text beside the image, tabular figures, and it is drawn only while serving and only above zero. It is suppressed in every other state, because a count left over from a working server beside a warning triangle is the one pair here that actively lies.

Rejected: the zero. A menu bar is shared, permanent and glanced at. “0” is a claim the reader has to parse and dismiss every time they look at the clock, and it says exactly what the icon on its own already says. Also rejected: a badge modifier, which the TRAP forbids; a coloured dot, since a status item image is template-tinted by the system and cannot be relied on to stay red; and pause.circle for stopped, which offers a play button this app does not have — the server's life is the app's life, so “stopped” here means it fell over, not that someone paused it.

One thing to measure before building it. WorktreeRegistry.projects() enumerates worktrees and then computes a whole change set per worktree to find out whether it is non-empty — one git process each, at a ten-second budget. That is the arithmetic behind the number in the menu bar, and it cannot run on a tick. Cache it, refresh on menu-open and on a slow timer, and never recompute it because the icon redrew.

Should feel like the Time Machine menu. A glance tells you it is fine; you open it twice a year, and when you do it is because something is not.

Open call b  ·  THE MENU

Keep “Pair a device”, and make it a door rather than a duplicate

Recommendation. Keep it, and have it open Settings on the Devices tab. There is one QR in the app and it lives in one place; this is a second door to that place, not a second implementation of it. The reason it earns the row is the constraint above it: under LSUIElement this menu is the entire app. A person holding a phone and looking for the QR has nowhere else to look.

Two consequences, both small. It is disabled when the server is not running, since the QR encodes host and port and there are none. And settingsRequests has to carry which tab was asked for, rather than being a bare counter — the request already goes through SettingsOpener, so this is a value on the request, not a new mechanism.

The status line should be a Button. It is a Text today, which the code correctly calls “present, legible and unclickable”. But the port is different on every launch — 59144, then 53613, then 53611 — so nobody memorises it; the only reason to read it is to paste it somewhere. Make the row copy http://macbook-pro.local:59144 and the fact becomes a tool. The count gets its noun on the line underneath, because a bare “3” in the menu bar cannot carry one.

Rejected. Dropping the item and letting Settings be the only route: it saves one row and costs the one gesture a new device needs. A “Copy address” item of its own: two rows for one fact. Putting the local-network fix behind an alert: the menu is where the reader already is, and a link there is one click instead of three.

Should feel like the Wi-Fi menu's top line. It tells you what you are on, and the thing you would do next is right there.

The measurement that sets the window
The pairing payload is granita://pair?host=&port=&code=&spki= with a 17-character host, a 5-digit port, 32 hex characters of code and a 44-character base64 digest: about 140 bytes once the digest is percent-encoded. In byte mode at error correction M that is QR version 8 or 9 — 49 to 53 modules. At the 4pt module that scans reliably from arm's length, plus the four-module quiet zone, the QR is 236–244pt square.
Stacked with the fallback words, the countdown and two paired devices, the Devices tab needs 560pt of height. The code's minHeight: 400 would make a person scroll to a QR while holding a phone up to it.
Open call a  ·  TAB ORDER

General, Projects, Devices, Connections, Advanced

Recommendation, and it disagrees with the specification twice. Five tabs, and Advanced last. The connection log is not an advanced setting — it is a live view of what is happening to this Mac, the only panel with a reason to be reopened, and the one thing here that is read under pressure. It gets its own tab, called Connections.

Advanced goes last because that is where every Mac app puts it, and because of what shares the tab: Reset All Data. Leaving the log there means the panel he opens while annoyed is one mis-click from the button that unpairs every device. Those two things should not be neighbours.

Order and selection are different decisions. Advanced is first in the code today for a good reason — it was the only tab worth opening. That reason expires the moment General and Projects exist, and it was never an argument about order: it was an argument about which tab opens first. So order them as above, restore the last-used tab after that, and select Projects on a first run, because until something is switched on the app does nothing at all.

Rejected. A sidebar in the System Settings shape: it is a bigger window for five one-word panes, and NavigationSplitView in a Settings scene buys navigation nobody needs at this depth. Rejected too: letting the window resize per tab. Apple's own do it, but between a 560pt QR pane and a three-row General pane the jump reads as a glitch — fix the width at 620 and let the height be the tallest tab's.

Should feel like Terminal's Settings. Five plain panes, opened rarely, none of them clever.

Open call d  ·  THIRTY FOUND, NONE ENABLED

The scan's results never enter this list uninvited

Recommendation. A scan opens a sheet, and its results stay in the sheet until they are chosen. What the sheet writes is “added, switched off”; the switch in the list is a second, separate act. That is what makes “thirty found, none enabled” read as deliberate: thirty things were found, and the tab never grew by thirty rows, so there is nothing to mistake for a broken import. The list only ever contains repositories a person named.

Three details carry it. The subtitle states the count and the folder, so the number is the scan's report rather than a surprise. There is no Select All — the one gesture that would make thirty repositories of private source code addable in a click. And the confirm button counts what it will do: Add 2 Repositories, disabled at zero, so the sheet cannot be dismissed into an ambiguous state.

Rejected. Listing candidates inline as disabled rows: one live row among thirty grey ones is exactly the broken import the call is worried about, and it turns the security list into a set of things you must check you have not switched on. Rejected: enabling straight from the sheet — one confirm, thirty repositories visible. Rejected: a “scanned” section in the tab, which gives the list two meanings and makes the toggle's blast radius depend on which section a row is in.

The row, in order. Switch, then name, then path, then what it costs. The switch is first because it is the only thing on the row with consequences, and left is where a Mac reader's eye starts. The path is monospaced and secondary because two projects can share a name and only the path settles it. The trailing figure is the honest reason to care: 4 worktrees, 2 with changes comes from Project.worktreeCount and dirtyWorktreeCount, which already exist, and it is what reconciles this tab with the number in the menu bar.

The moved folder, and a disagreement with the API. Today a project whose folder is gone still passes isVisible, so projects() serves it with zero worktrees — indistinguishable, on the phone, from a project with nothing to read. The row here says Folder not found, disables the switch, keeps the last known path in monospace and offers Locate…. The switch is disabled rather than silently flipped off, because turning off something a person turned on is a decision the app should not make while they are not looking.

Should feel like Full Disk Access in Privacy & Security. A short list of things you granted on purpose, each with a switch, and adding one is a deliberate trip through a folder picker.

§5  ·  TWO PREMISES BROKEN, ONE OF THEM SECURITY-SHAPED

The six words are a decoration until the server accepts them

Pairing.spoken(for:) takes code.prefix(6) and maps each hex digit to one of sixteen words. The code is 32 hex characters. So the words carry 24 bits of a 128-bit secret, and redeem(code:) looks up the whole code — a phone that is given the words has nothing it can send. As built, the fallback is a label.

Recommendation. Make the words the code rather than a view of it: redeem matches an issued code by its spoken form as well as its hex, so one secret has two encodings. 24 bits is enough here and only here: one code is live at a time, it dies after 120 seconds, it is single use, and five wrong guesses from an address cost that address a minute. Then the drawing follows the truth — the words sit at 13pt monospace directly under the QR, as an equal, not as small print.

And fix the word list while it is being read aloud. Sixteen words that include both amber and ember are one letter apart in the one situation where the channel is a person's voice or memory, and harbor is a spelling a British developer will type wrong. This is a Mac-side fix because the Mac is what prints them.

Last seen. StoredDevice holds pairedAt and no later timestamp, so “last seen” can only come from the in-memory log, which starts empty at every launch. The row therefore leads with the fact that is real — paired 3 August — and adds Seen 4 min ago only when this run has actually served that device. A device with no sighting says Not seen since 9:12, which is true, rather than a stale date that reads as an accusation.

Rejected. Persisting last-seen properly: JsonDocumentStore rewrites the whole document, and the store's own contract is “written rarely, read on every request” — a polling phone would turn every request into a disk write. If it is ever wanted, it is a coarse daily stamp written on change, not a timestamp per request. Rejected: a ring or gauge for the countdown, which invents a control; and no countdown at all, which leaves the worst state undrawn — a code that quietly expired looks exactly like a wrong code from the phone's side.

One sequencing note. The QR is specified as carrying spki=, and there is no identity yet — so this tab either ships in the same release as the TLS slice, or it ships with that warning under it and teaches a phone to trust a link it will have to refuse later. I would ship it with the identity. If it has to go first, the warning stays.

Should feel like the four-digit code an Apple TV puts on the television. Big, alive for a moment, pointed at rather than read.

§6  ·  DEFECT, IN THE TAB THAT SHIPS

The source column names this Mac, not the phone

request.head.authority is the authority the client asked for — the host and port it dialled. Every device on the network dials the same one, so every row in this panel carries the same string, and ConnectionAttempt.source's own comment — “the address is the only thing that distinguishes two of them” — describes something the value cannot do.

Three consequences, in increasing order of seriousness. The panel cannot tell two phones apart. The coalescing rule collapses different devices with the same outcome into one row, so “one polling phone cannot fill it” also means one polling phone can hide another. And FailedAttempts is keyed on the same string: five bad tokens from anything on the LAN blocks every device, including the paired one, for a minute. The specification says per source address, and the actor's own comment says one phone must not lock the others out. Both are currently untrue, and this panel is the only place it would ever be visible.

Recommendation. Key both the log and the limiter on the channel's remote address, which means a request context that carries it — the router is generic over its context type, and BasicRequestContext does not. Then coalesce on the address without the port: a new TCP connection gets a new ephemeral source port, so an address:port key would defeat the coalescing the moment it starts working. That is one value and one key, and the layout below is what it buys.

Open call e — yes, in kind, and the kind is “is there anything to do”. A served row is a receipt. A refused row is a to-do, and it gets the one affordance the served row does not: Pair… for no token, Pair Again… for a token this Mac did not issue — the two refusals a person can actually fix from here. Version skew and rate limiting get no button, because there is nothing on this Mac to press. Same list, same order, one axis of difference that means something.

Two edits to what the row says. Drop the word “Refused”: the xmark.circle already says it, forty-five times down a list, and the space pays for the address and the count. And print the repeat count — the coalescing is right, but as built it turns four hundred attempts into a row that looks like one, and “my phone tried once” against “my phone has been hammering this for ten minutes” are different problems.

Rejected. Colour as the difference: during setup nearly every row is a refusal, and a wall of red stops being a signal. Sections or a filter picker: this log is read once, in anger, and sorting destroys the newest-first order that makes it readable. A Table with sortable columns: that is a database inspector for fifty rows held in memory. Kept exactly as written: the empty state. “Nothing has tried to connect”, with “every device that reaches this Mac appears here, whether or not it gets in” — it is the best sentence in the app, because it tells you the panel is working when it is showing you nothing.

Should feel like Console, if Console only ever answered one question. You arrive annoyed and you leave knowing which end is wrong.

What I could not decide from here

Whether the count in the menu bar is affordable. Producing it means enumerating worktrees and computing a change set per worktree, which is a git process each at a ten-second budget. On your machine, with your projects enabled, time projects() once. If it is tens of milliseconds, cache it and refresh on a timer. If it is seconds, the number belongs behind opening the menu, and the label is the icon alone — which is a smaller change to this drawing than to the code.

Whether Devices ships before the identity. I have drawn it as though it ships now, with the warning. The other reading is that pairing is not a feature until there is something to pin, and that a QR shipped early trains a phone to accept a link it must later refuse. That is a release decision, not a layout one, and it is yours.

The window's real minimum. Everything here is drawn at 620 × 560, and the height comes from the QR arithmetic rather than from a screen. Your own notes say window geometry is not measurable from outside the app while Stage Manager is on, so this one has to be asserted from inside — which is also the moment the Mac gets the snapshot kind it does not have yet. These frames are drawn at 1:1 so they can be the baselines.

One thing I did not touch: the store's lock file. Both the executable and this app will open the same document today, and the only surface that could ever say so is Advanced. It is not drawn because I do not know what you want to happen when it is held — refuse to start, or serve read-only. That is a question, not an omission.
